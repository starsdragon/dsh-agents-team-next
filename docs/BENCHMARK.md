# 实测对比（2026-10）

> 本页是维护者在本机真实任务上的**端到端观察记录**，不是受控 A/B 基准：每个场景只跑了一轮，跨 harness 对比存在混杂因素。所有数字来自会话用量统计与会话界面显示的缓存命中率，未做二次加工。

## 测试环境

- Harness：DSH（Web profile，Agent Team 启用）
- 模型路由：`opencode-go / DeepSeek V4.1 Flash`（下称 4.1f）；主会话 `reasoning_effort = max`
- 插件：`dsh-agents-team-next` v0.3.3（本仓库）
- 任务类型：Three.js / 前端交互类真实交付任务

## 结果

| # | 场景 | 内容 | 总花费（token） | 缓存命中 |
|---|---|---|---|---|
| 1 | 键盘建模 | Three.js 交互式机械键盘产品页：3D 建模 + HTML/CSS 配置界面、配色/主题组合、拆解动画、键位体验、本地持久化 | **8.8M** | **93%** |
| 2 | 中国古建筑体素建模 | 体素化中国古建筑场景 | **11.5M** | **93%** |
| 3 | 余烬谷 | 原创场景《余烬谷》 | **19.7M** | **98%** |

## 场景一：跨 harness 对照

| 方案 | 总花费 |
|---|---|
| DSH + 本插件 | 8.8M token |
| ZCode + 同一模型（4.1f），同一任务 | 约为前者的 2 倍 |

**口径说明**：跨 harness 对比包含系统提示、工具集、编排方式等差异，差距不能全部归因于本插件。本插件在其中的作用是：档位按任务分配（而不是一律满载）、派发上下文压缩、以及完成纪律减少"已完成还继续改"的回合。

## 怎么读这些数字

- **缓存命中是会话聚合口径**。每个会话的第一个请求必然全冷（请求前缀首次出现），命中率随回合数增加而上升——场景三（19.7M）回合最多，所以显示 98%。
- 会话中段的命中波动主要来自**运行时上下文更新**（文件变化触发系统区快照重渲染）与单轮新增内容，不是插件造成的逐请求失效：插件的系统提示 section 是静态文本，首个请求之后保持不变（实测中第二个请求的未命中仅 575 token，其余前缀全部命中）。
- 总花费为输入 + 输出 token 的会话累计；缓存命中的输入通常按更低价计费，实际账单比例与命中率不完全线性。
- 命中率/花费取决于任务长度、回合数、上下文更新频率与工具构成，以上数字仅供参考，不构成性能承诺。

## 复现建议

1. 按 README 安装插件并重启 DSH Host；
2. 开新会话跑同类任务（Three.js 交互页、体素场景等）；
3. 记录会话总 token 与缓存命中，与同等规模的基线任务对比。
